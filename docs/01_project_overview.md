# Pick-to-Belt — Опис проекту

## Загальна концепція

**Pick-to-Belt** — система автоматизації складського комплектування замовлень. Основна ідея: продукти зберігаються у фізичних лотках, кожен з яких підключений до сервопривода. Коли оператор запускає комплектацію, система автоматично відкриває потрібні лотки на конвеєрну стрічку, а позиції, яких немає у системі, підтверджуються вручну.

Проект реалізований на **Flask + SQLAlchemy**, розгорнутий у Docker на **Raspberry Pi** (ARM64), керує сервоприводами через шину **I2C (PCA9685)**.

---

## Реалізований функціонал

### 1. Управління товарами (16 слотів)

- Підтримка 16 позицій (каналів 0–15 на одному PCA9685 з адресою `0x40`)
- Кожен товар прив'язаний до конкретного каналу сервопривода
- Для кожного товару зберігається:
  - Артикул та назва
  - Поточний залишок та ємність лотка
  - Фізичні розміри та вага
  - Фото товару
  - Кількість стікерів та опис до них
  - Коментар для оператора
- Завантаження фото товару (PNG, JPG, GIF, WebP, до 16 МБ)
- Швидка ініціалізація 16 тестових товарів одною кнопкою

### 2. Управління коробками

- Довідник типів коробок з розмірами (довжина × ширина × висота)
- Швидка ініціалізація 5 стандартних розмірів (XS → XL)
- При старті комплектації оператор обирає тип коробки для замовлення

### 3. Обробка замовлень

**Статусна модель замовлення:**
```
pending → picking → packed → done
```

- Завантаження замовлень з JSON-файлу (`data/orders_test.json`)
- Кожне замовлення містить список позицій (артикул + кількість)
- Оператор обирає коробку та запускає комплектацію
- Система автоматично визначає, які позиції є в серво-системі, а які потребують ручного збору

### 4. Автоматичне комплектування (Servo)

- При запуску замовлення в окремому потоці виконується `_pick_order()`
- Для кожної позиції:
  - Знайдено товар у БД і є залишок → сервопривод відкриває лоток N разів
  - Недостатній залишок → позиція отримує статус `partial`, оператор підтверджує вручну
  - Товар відсутній у системі → позиція отримує статус `manual`
- Сервопривод: відкрити лоток → витримати 0.6 с → закрити (для кожної одиниці з паузою 0.5 с)
- Списання залишків та запис у лог (StockLog) відбувається автоматично

### 5. Ручне підтвердження

- Позиції зі статусом `manual` або `partial` відображаються в інтерфейсі оператора
- Оператор фізично кладе товар у коробку та натискає кнопку підтвердження
- Після підтвердження всіх позицій стає доступна кнопка "Запаковано"

### 6. Звітність

- Аналітика за обраний період (сьогодні / 7 / 30 / 90 днів)
- Показники: кількість замовлень, позицій, одиниць (авто + вручну)
- Топ-10 найпопулярніших товарів за кількістю відвантажень

## Технічний стек

| Компонент | Технологія |
|-----------|------------|
| Backend | Flask 3.x + Flask-SQLAlchemy 3.x |
| База даних | SQLite (`data/pick_to_belt.db`) |
| Hardware | PCA9685 I2C PWM driver (smbus2) |
| Frontend | Vanilla JS + HTML/CSS (без фреймворків) |
| Контейнеризація | Docker (ARM64 / Raspberry Pi) |
| CI/CD | GitHub Actions → ghcr.io → self-hosted runner |

---

## Режим симуляції

Якщо апаратне забезпечення (I2C / smbus2) недоступне, система автоматично переходить у режим симуляції. В цьому режимі всі команди сервопривода логуються, але не виконуються фізично. В інтерфейсі відображається значок "SIMULATION".

## Розгортання

```bash
# Локально
python run.py  # http://localhost:5000

# Docker (Raspberry Pi)
docker compose up -d
```

**Порти:** 5000 (HTTP)
**Постійні дані:** `./data/` (SQLite), `./static/uploads/` (фото товарів)
**I2C пристрій:** `/dev/i2c-1`
